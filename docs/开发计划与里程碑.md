---

## 1. 计划原则

1. **先打通主流程，再扩展家族**：优先“导入 → 全自动管线 → 2D → 报告”，再攻 3D 与实时流。
2. **高风险前置**：Mayavi 打包、5GB 性能、沙箱安全、结构化输出差异必须在 P1–P2 做 Spike。
3. **每阶段可演示**：每个里程碑都有可运行版本与验收用例，不做“最后一次性集成”。
4. **版本纪律**：每个合并 PR = 一个 squash commit = 一次 patch 版本；CHANGELOG 与 tag 同步。
5. **文档随代码**：接口、Scene JSON、图表注册表、ADR 与实现同步更新。
6. **安全与许可贯穿**：gitleaks、依赖审计、Qt/FFmpeg 许可从 P0 开始，不留到最后。

## 4. 关键路径与依赖

```text
P0 规范/CI/Spike
  → P1 数据接入/画像/工程
    → P2 AI 编排/选图/成本
      → P3 2D/地图/网络/影像
        → P4 3D 双后端
          → P5 报告/追溯/安全
            → P6 性能/打包/发布
```

**关键路径风险点：**

1. P0-08 Mayavi 打包失败 → 直接影响 P4 与发布。
2. P1-12 5GB 性能不达标 → 影响 P6 性能验收。
3. P2-09 选图质量不达标 → 影响盲评与产品价值。
4. P4-04/P4-05 3D 渲染不稳定 → 影响科研定位。
5. P5-07 沙箱被绕过 → 阻断发布。

## 7. 质量门禁与发布节奏

- **每个 PR：** CI 全绿 + 审查通过 + VERSION/CHANGELOG 更新 + squash merge。
- **每周：** 一次集成构建；更新风险登记；演示可运行版本。
- **每个里程碑：** 打 minor tag；更新文档；用户确认。
- **发布前：** P0/P1 缺陷清零；P2 有修复计划；安全扫描通过；许可审计通过。

## 8. 风险与应对（项目视角）

| 风险 | 触发信号 | 应对 |
|---|---|---|
| 3D 打包失败 | Spike 超时/依赖冲突 | 切换到 trame 或纯 VTK 离屏；降低 Mayavi 承诺 |
| 性能不达标 | 500MB >3 分钟 | 启用 DuckDB 下推、列裁剪、降采样；调整指标需变更 |
| 选图质量低 | 盲评 <80% | 扩充注册表与规则；增加 few-shot；限制候选集 |
| 沙箱绕过 | 安全测试失败 | 收紧白名单；移除危险库；提供 Docker 可选 |
| 范围膨胀 | 新需求不断 | MoSCoW 重排；新需求进入 v1.1 |
| 双仓库泄露 | gitleaks 告警 | 停止发布；轮换密钥；清理历史；复盘 |
| 单人开发延期 | 关键路径延迟 | 按 48 周上限排期；引入外部评审；延期优先于降质；不擅自削减范围 |
