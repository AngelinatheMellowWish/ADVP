## 1. 引言

### 1.1 目的

本文档定义 ADVP（Automated Data Visualization Platform）v1 的功能需求、非功能需求、数据需求、接口需求、验收标准与范围边界，作为产品设计、开发、测试、验收和版本管理的唯一需求基线。

ADVP 的目标是构建一条由大语言模型（LLM）驱动的数据可视化全自动管线：用户提供数据后，系统自动完成**提取（Extract）→ 理解与分析（Analyze）→ 清洗与处理（Process）→ 图表选型（Select）→ 渲染与展示（Visualize）→ 报告与导出（Report）**，并在科研三维可视化场景中提供接近 Mayavi 的专业能力。

### 1.2 范围

**包含：**

- Windows 10/11 x64 本地 Web 应用，单用户使用。
- OpenAI 兼容与 Anthropic 兼容两类模型服务的自定义 Base URL、API Key、模型名配置。
- 结构化数据、科学数据格式、体数据/影像、SQL 数据库、远程 URL/云存储、实时流的接入。
- PDF/Word 表格抽取与网页 URL 数据抽取；**不包含 OCR/扫描件识别**。
- 单文件 500MB–5GB 的本地处理能力。
- 统计 2D 图表、3D 科学图表、地图/地理空间、关系网络/桑基/旭日图、时序/实时刷新、影像切片与叠加六类图表家族。
- 基于“规则筛选 + AI 决策 + 自动评分重选 + 低置信度 Top3 兜底”的图表选型。
- 混合 3D 渲染：浏览器 WebGL（VTK.js）负责常规交互，服务端 Mayavi/VTK（含 trame 交互模式）负责体渲染、复杂流场与大网格。
- 交互式结果、PNG/SVG/PDF、MP4/GIF、独立 HTML、可复现 Python 脚本/Notebook、Markdown/PDF 报告。
- 全链路可追溯、工程保存、成本可见与预算控制、离线只读与重渲染。
- 中英双语界面、深色科研风视觉、高保真原型。
- 开源（Apache-2.0）、双仓库（公开脱敏 + 私有全量备份）、自动化 CI 门禁、严格版本管理。

**不包含（v1 明确排除）：**

- 多用户、账号体系、权限管理。
- 移动端/平板适配与实时协作。
- OCR、扫描件、图片文字识别。
- 本地模型（Ollama/vLLM 等）。
- SaaS 云端部署、多租户、托管服务。
- 非 Windows 平台。
- 对生成代码提供强隔离的 Docker/虚拟机沙箱（v1 使用受限子进程）。
- 数据合规认证（等保、HIPAA、GDPR 认证等）；仅提供基础隐私控制。

## 2. 总体描述

### 2.1 产品愿景

让不具备编程能力的科研人员与分析师，仅通过导入数据和自然语言描述，即可获得**统计正确、视觉合理、可解释、可复现**的可视化结果；让具备编程能力的用户能够查看、修改并导出完整代码与数据血缘。

ADVP 不以“生成一张图”为终点，而以“完成一次可追溯的数据分析任务”为终点。

### 2.2 目标用户与典型场景

| 用户类型 | 核心诉求 | 典型场景 | 关键成功指标 |
|---|---|---|---|
| 数据分析师/业务分析 | 快速从表格数据得到结论与图表 | 上传 CSV/Excel，自动生成多图仪表盘与分析摘要 | 首次出图 ≤3 步；图表可直接用于汇报 |
| 科研/工程人员 | 3D 科学可视化、体渲染、流场、影像 | 导入 NetCDF/HDF5/DICOM，生成等值面、体渲染、切片与动画 | 科学保真度；可导出论文级图 |
| 开发者/算法工程师 | 可复现、可二次开发 | 查看管线代码、导出 Notebook、嵌入自有系统 | 代码可运行；API/数据契约清晰 |

### 2.4 设计原则

1. **自动化优先，人工可介入**：默认全自动完成，用户可随时通过对话修正或回退单步。
2. **可解释**：图表选型必须给出理由；关键步骤展示输入、输出、模型、提示词版本与生成代码。
3. **可复现**：任意结果均可通过“数据哈希 + 处理配方 + 场景 JSON + 代码版本 + 模型参数”重建。
4. **科学保真**：坐标、单位、色标、统计变换必须显式记录；不得为了美观篡改数据。
5. **本地优先与最小外发**：原始数据默认留在本地；默认仅向模型发送元数据与样本。
6. **安全默认**：密钥不落明文、生成代码禁网、工作区隔离、依赖可审计。
7. **开放与可扩展**：图表注册表、渲染后端、Provider 适配器均为插件式接口。

### 2.5 假设与依赖

| 编号 | 假设/依赖 | 影响 |
|---|---|---|
| A-01 | 用户拥有可用的 OpenAI/Anthropic 兼容服务账号与配额 | 无可用服务时 AI 管线不可用 |
| A-02 | 运行时具备稳定网络访问模型服务 | 离线时仅支持非 AI 功能 |
| A-03 | 目标机器最低 16GB 内存、4 核 CPU；推荐 32GB 内存、8 核 CPU | 影响 5GB 数据处理与 3D 渲染可行性 |
| A-04 | 用户对导入数据拥有合法使用权 | 合规责任由用户承担 |
| A-05 | 用户机器允许安装本地应用并写入用户目录 | 影响安装与凭据库使用 |
| A-06 | Mayavi/VTK 在目标 Windows 环境可稳定打包与运行 | 影响 3D 后端交付风险 |
| A-07 | 用户按指导创建 GitHub 公开与私有仓库并完成登录 | 影响推送与协作 |

### 2.6 约束

- **C-01**：仅 Windows，不承诺 macOS/Linux（D14）。
- **C-02**：v1 不做 OCR、不做本地模型、不做多用户/SaaS（D34）。
- **C-03**：原始数据只保存路径引用与哈希，不默认复制进工程（D30）。
- **C-04**：生成代码仅在本地受限子进程中执行，禁网、限资源、仅工作区读写（D33）。
- **C-05**：API Key 仅存 Windows 凭据管理器，任何日志、工程文件、Git 仓库不得出现明文（D10/D42）。
- **C-06**：项目采用 Apache-2.0；依赖许可需与 Apache-2.0 兼容，不得引入 GPL/AGPL 代码（D28）。
- **C-07**：所有变更遵循 SemVer patch 递增、CHANGELOG 记录、PR + CI 门禁（D38/D39/D43）。
- **C-08**：开发周期 40–48 周（单人开发、全范围不削减；D21 修订）。
- **C-09**：公开仓库仅包含源码、文档、原型与 CI；私有仓库保存全量备份（D40）。

| 数据类别 | 留存位置 | 默认策略 | 是否入库 |
|---|---|---|---|
| 原始数据 | 用户原路径 | 只读引用 + 哈希，不复制 | 否 |
| 派生数据 | ADVP Workspace | 保留至工程删除；可配置 30 天清理 | 否 |
| 工程元数据 | ADVP Workspace | 保留；支持导出/备份 | 否（公开仓库） |

| 密钥 | Windows Credential Manager | 用户删除前保留 | 否 |

### 5.3 数据契约

- **Tabular Schema**：字段名、语义类型、物理类型、单位、缺失策略、值域、基数、来源列。
- **Array Schema**：维度、坐标轴、单位、索引顺序、切片范围、NoData 值。
- **Scene JSON**：`version`、`data`、`geometry`、`fields`、`camera`、`lighting`、`colormap`、`transferFunction`、`clipping`、`annotations`、`animation`、`backend`。
- **Pipeline Manifest**：步骤 ID、输入哈希、参数、模型/提示词版本、输出哈希、时间、成本。
- **Project Schema**：`schemaVersion`、`createdAt`、`updatedAt`、`datasets`、`recipes`、`charts`、`reports`、`providersRef`、`settings`。

### 5.4 数据外发策略

1. 默认：字段名、类型、统计量、前 100 行样本（可通过设置调整行数，上限 1000 行或 1MB）。
2. 敏感字段默认脱敏（邮箱、手机号、身份证号、地址、长文本）。
3. 全量发送：Provider 级开关 + 每次任务二次确认 + 追溯记录。
4. 外发前预览：展示将发送的 JSON/文本摘要，可复制检查。
5. 禁止外发：密钥、文件绝对路径（可配置脱敏为文件名）、日志全文、其他工程数据。

### 6.4 本地接口

- 后端 REST API + SSE/WebSocket；仅回环地址；启动令牌。

- GitHub 公开仓库（脱敏）：源码、文档、原型、CI。

- CI：ruff、mypy、pytest、eslint、tsc、vitest、gitleaks、commitlint、markdownlint、链接检查、依赖审计。
- 分支：`main` 保护；功能分支 + PR；squash merge；PR 必须通过 CI 与审查。

## 7. 架构与选型摘要

> 详细对比与理由见《技术选型摘要》。

### 7.1 逻辑架构

| 层 | 组件 | 职责 |
|---|---|---|
| 表现层 | React + TypeScript + Vite | 工程管理、数据预览、管线进度、2D/3D 工作台、报告、设置、追溯 |
| API 层 | FastAPI + Pydantic v2 | REST、SSE/WebSocket、鉴权令牌、任务编排入口 |
| 任务层 | Huey + SQLite（或等价轻量队列） | 后台任务、并发上限 2、重试、取消、进度 |
| 数据层 | DuckDB/Polars/xarray/h5py/pydicom/nibabel | 读取、画像、清洗、降采样、聚合 |
| AI 层 | Provider Adapter + Prompt Registry + Orchestrator | 结构化输出、重试/降级、成本核算、上下文裁剪 |
| 选图层 | Chart Registry + Rule Engine + Scorer | 候选筛选、AI 决策、评分重选、Top3 |
| 渲染层 | Plotly/ECharts/VTK.js/deck.gl/Cytoscape | 2D、地图、网络、常规 3D |
| 科算渲染层 | Mayavi/VTK + trame | 体渲染、流场、大网格、动画 |
| 存储层 | 工程 JSON + 派生数据 + 日志 + 凭据引用 | 持久化、追溯、清理 |
| 安全层 | 沙箱、审计钩子、CSP、gitleaks | 代码执行隔离、密钥保护、内容安全 |

### 7.2 数据流

```text
数据源 → 连接器/抽取器 → 标准化 Schema → 画像/质量报告
      → 清洗配方（可撤销）→ 派生数据集
      → AI 分析（元数据+样本）→ 图表候选 → 规则筛选 → AI 选型/评分
      → 2D/3D 渲染 → 交互视图/静态图/动画/报告
      → 追溯 Manifest + 成本记录 + 版本记录
```

### 7.3 部署形态

## 9. 验收标准

> 完整可执行验收用例见《验收标准》。本章定义验收门槛。

### 9.1 功能验收

- 六类数据源各至少 3 个样例（含异常样例）导入成功或给出可操作错误。
- 默认全自动管线在 10 个跨领域数据集上完成“导入→报告”，无阻断性错误。
- 六类图表家族各至少 2 种图表可交互、可导出、可追溯。
- PDF/Word/网页抽取可人工校正；无 OCR 能力时不误导用户。
- 3D 混合后端在同一 Scene JSON 下均可渲染；无 GPU 时自动降级。
- OpenAI/Anthropic 兼容接口均可配置、测试、调用；主备切换生效。
- 密钥不出现在日志、工程、导出物与 `git grep` 结果中。
- 生成代码在沙箱内执行，网络访问与工作区外写入被阻止。
- 中英文切换完整；10 个原型页面与实现一致（允许合理差异）。

### 9.2 性能验收

按 NFR-PERF-001～007 执行；测试数据集、硬件配置、测量脚本纳入仓库。结果记录在验收报告中。

### 9.3 质量验收（图表选型）

- 3 名评审对不少于 30 个数据集/分析意图进行盲评。
- 评审只看到数据特征与最终图表，不知道来源策略。
- 评分维度：适配性、可读性、信息完整性、科学正确性。
- “合理或优秀”比例 ≥80%；严重误导（如 3D 饼图用于精确比较）≤2%。
- 低置信度 Top3 触发时，Top3 中包含人工首选的比例 ≥90%。

### 9.4 安全验收

- gitleaks 全历史扫描通过；依赖高危漏洞为 0（或已记录例外与缓解）。
- 沙箱逃逸测试：网络连接、工作区外写入、子进程创建、危险导入均被阻止。
- 本地服务仅回环可达；无启动令牌的请求被拒绝。
- 全量外发必须二次确认并留痕；默认外发内容不含敏感样本。

### 9.5 文档与版本验收

- 需求书 md 与 docx 内容一致；docx 可正常打开、目录/页码正确。
- 技术选型、验收标准、页面清单、开发计划、确认清单齐全。
- 每个 PR 通过全部 CI 检查；VERSION、CHANGELOG、tag 与全部版本文档一致；当日工作记录已更新。
- 公开仓库无敏感信息；私有仓库可完整恢复项目。
- 10 页高保真原型可在浏览器离线打开。

### 9.6 完成定义（Definition of Done）

功能实现 + 自动化测试通过 + 文档更新 + 当日工作记录更新 + CHANGELOG/VERSION 更新 + 安全扫描通过 + 代码审查通过 + 验收用例通过 + 私有仓库推送完成；公开仓库按里程碑同步。
